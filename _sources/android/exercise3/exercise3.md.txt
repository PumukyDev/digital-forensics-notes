# Android and IOS forensics advanced

This exercise simulates a real-world scenario in which a forensic analyst must extract, preserve, and examine digital evidence from a mobile device, combining physical imaging techniques with manual analysis of artifacts generated by the applications installed and configured on the handset.

## Manual Android Forensics

This scenario focuses on the examination of an Android 11 device — a Google Pixel 3 — that has undergone a controlled forensic imaging process. The most relevant details are summarized below.

### System and Android version details

The device runs Android 11 with a stock Google image (Build: RP1A.200720.009, Patch Level: September 5, 2020).

- Make: Google Pixel 3
- Model: G013A
- Storage: 64 GB
- RAM: 4GB
- Carrier: Google Fi
- Phone Number: 919-579-4674
- Serial: 8CEX1N716
- Wi-Fi MAC: 7c:d9:5c:ac:a2:cf
- BT MAC: 7c:d9:5c:ac:a2:ce

### Forensic image generation process

The procedure begins with a factory reset by flashing a stock image. The following critical steps are then carried out:

- **Device setup:** A Google Fi account is added to enable cellular service.
- **Privileged access:** The bootloader is unlocked and Magisk is installed, providing the root access required to extract protected data.
- **Data population:** 46 non-stock applications (in addition to the pre-installed apps) are installed from Google Play and populated with user data through their normal functionality.
- **Data extraction:** A logical extraction of the phone's memory contents was performed using **Magnet Acquire**. Download it [here](https://drive.google.com/file/d/1AiMDFlSRHuEeAxw4mgzlISnflB_DB-D9/view). The extraction log output is available [here](https://drive.google.com/drive/folders/16ws1Bk0i03O58X8z2oRJNMYvRQKDZlFo).

### Purpose and analysis tools

The main objective of this exercise is to identify and manually analyze the forensic artifacts contained on the Android device, enabling reconstruction of user events and activity. The following tools are recommended:

- **FTK Imager:** For obtaining forensic artifacts from Android images.
- **Complementary tools:** DB Browser for SQLite to query database artifacts directly; Autopsy or MOBILedit for detailed analysis of records, metadata, and residual data in applications and the system; Notepad++ or similar editors for plain text, hexadecimal, Base64, XML, and other encodings.

13. Application and device activity

`sqlitebrowser data/data/com.google.android.as/databases/reflection_gel_events.db`

This database was **not present** on the extracted image. In a complete acquisition, it would be expected at the path above.

`reflection_gel_events.db` stores data used by **Device Personalization Services (DPS)**, which collect usage statistics to predict and suggest applications and content to the user. A notable forensic characteristic of this database is that it may retain records of applications that were later uninstalled from the device. Artefacts from `reflection_gel_events.db` can help build a detailed timeline of device events over a longer period than Digital Wellbeing data alone. In this case, the file was not found on the device.

20. Signal messages

- `/data/user/0/org.thoughtcrime.securesms/databases/signal.db`
- `/data/misc/keystore/user_0/10244_USRSKEY_SignalSecret`
- `/data/user/0/org.thoughtcrime.securesms/shared_prefs/org.thoughtcrime.securesms_preferences.xml`

These artifacts are encrypted and cannot be read directly. The expected decryption workflow is as follows:

Signal encrypts its database using **SQLCipher** with **AES-GCM**. The process works in two stages: first, the SQLCipher key is obtained; then an AES-GCM key derived from `USERKEY + IV` is used to protect the database. These values are stored in `org.thoughtcrime.securesms_preferences.xml`. To access the message content, the process must be reversed to recover the SQLCipher key.

At the time of this analysis, decryption of the Signal database was not achieved — the relevant files are present but remain inaccessible without the derived key material.

## Automated iOS Forensics

### Objective

Perform a forensic analysis of an iPhone SE device, extracting and interpreting relevant digital artifacts using iLEAPP from a logical backup obtained without jailbreak (checkra1n utility).

### Device details

- Make iPhone SE
- Model A1662 (Rose Gold)
- Order Number MLXL2LL/2
- RAM 2 GB
- Storage 64 GB
- Carrier Google Fi
- Phone Number 919-579-4674
- Serial DX3T126VH2XV
- Wi-Fi MAC A0:D7:95:79:DD:A1
- BT MAC A0:D7:95:79:DD:A2
- iOS Version 13.4.1 (Build 17E262)
- Passcode 0731

### Forensic acquisition

1. **Acquisition method:** Logical backup via iTunes. Download the backup file [here](https://drive.google.com/file/d/1npTXJTNtt2gmMhJ8fAw0FFuq7XBsjcwf/view).

- Output format: `.zip` archive.
- Encrypted backup password: `mypassword123`
- The device was **not** jailbroken.

2. **Acquisition method:** Magnet Acquire full device dump. Download the device image [here](https://drive.google.com/file/d/1j7fUmxzmk_R2fWP9v1XFPGfEef3wUAXd/view). This image will be used for the second report generated later in the exercise.

### Tools

**iLEAPP (iOS Logs, Events, and Preferences Parser)**

- Developed by Alexis Brignoni and Yogesh Khatri.
- Parses iTunes/iOS backups to extract forensic artifacts.

**iTunes Backup Explorer**

- Decodes and transforms iOS backup folders for analysis.


## Procedure

### 1. Environment setup

- Use a Windows, Linux, or macOS host.
- Download and run iLEAPP from the [official repository](https://github.com/abrignoni/iLEAPP):

```bash
wget https://github.com/abrignoni/iLEAPP/releases/download/v2.5.0/ileappGUI-v2.5.0-Linux_x86_64.AppImage
chmod +x ileappGUI-v2.5.0-Linux_x86_64.AppImage
./ileappGUI-v2.5.0-Linux_x86_64.AppImage
```

### 2. Extract and decode the backup

- Unzip the backup `.zip` archive into a local folder.
- Decode the extracted backup folder using **iTunes Backup Explorer**. When prompted, enter the password: `mypassword123`.

```bash
unzip c623fbd7e91b041e07a68f8523f53a35973e475d.zip
mkdir input output
wget https://github.com/MaxiHuHe04/iTunes-Backup-Explorer/releases/download/v1.7/itunes-backup-explorer_1.7_debian_x64.deb
sudo apt install ./itunes-backup-explorer_1.7_debian_x64.deb
```
